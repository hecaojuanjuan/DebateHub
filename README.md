# DebateHub · 社区辩论训练平台

初期服务「宁诺例辩」，支持多个独立社群。成员通过邀请链接或二维码，以昵称加入，在辩题下选择持方、发表观点和回复。

## MVP 已实现

- 社群默认私密；群主可切换为公开。私密社群的辩题、持方和评论由服务端隔离。
- 群主从已加入的成员中添加或撤销管理员，权限仅在当前社群生效。
- 群主与管理员发布辩题、生成有效期 7 天的邀请二维码、结束或重新开放讨论、移除不当观点。
- 成员选择正方／反方，发表观点、回复讨论、按持方筛选和时间排序。
- 持方人数、比例、评论和角色约每 2 秒同步；页面隐藏时暂停同步，返回页面时重新读取。
- 每人每题只有一个当前持方；改变持方不改变历史发言的立场。
- 浏览器身份使用 30 天 HttpOnly Cookie；数据库仅保存会话和邀请凭证的 SHA-256 摘要。
- 支持手机布局、邀请链接复制、二维码 SVG 下载、社群切换与新建社群。

| 查看私密社群内容         | ✓    | ✓      | ✓    | —          |
| 查看公开社群内容         | ✓    | ✓      | ✓    | ✓          |

| 生成或撤销邀请           | ✓    | ✓      | —    | —          |
| 移除他人的观点           | ✓    | ✓      | —    | —          |
| 设置社群公开／私密       | ✓    | —      | —    | —          |

任何成员都能移除自己的发言。移除正文后保留回复关系。首版暂不提供群主转让、移出成员、账号找回、附件或点赞。

## 本地启动

环境：Node.js 22.13+，pnpm 11.25。应用代码在 `app/`。

```powershell
cd app
pnpm install --frozen-lockfile
pnpm db:local
pnpm dev
```

打开终端打印的地址，默认为 `http://127.0.0.1:5173`。`db:local` 应用尚未执行的迁移；首次运行会在忽略跟踪的 `app/.dev.vars` 中生成随机 `ADMIN_KEY`。

在宁诺例辩首页点击「我是管理员」，输入 `.dev.vars` 中的口令，进入初始群主身份。不要把口令发给成员或普通管理员；管理员应由群主在成员列表中任命。

浏览器昵称身份需要保留 Cookie。清除 Cookie、退出或会话过期会失去该身份；私密社群需要重新邀请。初始宁诺群主可通过管理员口令重新登录；其他昵称群主在首版暂不支持身份找回，因此建议试用期间保留登录，并任命至少一位管理员协助运营。

## 每周使用

1. 群主／管理员点击「发布辩题」，填写辩题、背景与双方立场。
2. 点击「邀请伙伴加入」，复制链接或下载二维码，发送给社员。邀请转发给谁，谁就可以使用；过期或撤销后无法加入。
3. 社员扫码，输入 2–20 字昵称，选择持方后发言。
4. 群主从「管理社区与讨论 → 管理成员」添加管理员。被任命成员无须共享口令。
5. 训练结束时「结束讨论」，保留历史持方和讨论供复盘。

## 上线

前端为 React + TypeScript，使用 Vinext 的路由和 Cloudflare Workers 运行时，结构化数据存储于 Cloudflare D1（SQLite）。

- `.openai/hosting.json` 保存已有 Sites 项目 ID 和 `DB` 绑定，不存放口令。
- `db/schema.ts` 是数据结构定义，`drizzle/` 保存增量 SQL 和迁移元数据。
- 上线前在托管平台配置秘密环境变量 `ADMIN_KEY`，并应用全部迁移。
- 网站入口需要允许公网访问，社群是否公开由应用内的群主设置。初始社群仍为私密。
- 使用线上域名生成邀请二维码；`127.0.0.1` 的本地二维码不能供其他手机远程访问。
- 发布流程需同步源码到 Sites 的托管源码仓库；本项目未经明确授权不会自动执行 Git 提交或推送。

当前为单社团小规模训练的 MVP：全量读取选中辩题的评论并轮询同步。规模扩大后应增加分页、增量同步、独立身份认证、成员移除与账号恢复；D1 数据在重新发布后保留，本地和线上数据库相互独立。

详细模块与接口见 [架构说明](docs/architecture.md)。
