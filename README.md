# DebateHub · 社区辩论训练平台

初期服务「宁诺例辩」，支持多个独立社群。成员通过邀请链接或二维码，以昵称加入，在辩题下选择持方、发表观点和回复。

## MVP 已实现

- 社群默认私密；群主可切换为公开。私密社群的辩题、持方和评论由服务端隔离。
- 群主从已加入的成员中添加或撤销管理员，权限仅在当前社群生效。
- 群主与管理员发布辩题、生成有效期 7 天的邀请二维码、结束或重新开放讨论、移除不当观点。
- 群主和管理员均可查看全部成员、同意或拒绝入群申请、移出普通成员；群主也可移出管理员。
- 默认邀请直接加入。群主可在设置中开关「入群需审核」；开启后，注册、昵称加入和已有账号登录均等待审核后才能参与。
- 成员和管理员可自行退出当前社群，保留账号、其他社群及历史观点和投票。被移出或被拒绝的用户再次加入时始终需审核。
- 群主和管理员可修改辩题、撤回及恢复。撤回时向成员和访客隐藏全部内容，管理端保留记录。已有参与后不能改动双方立场名称。
- 成员选择正方／反方，发表观点、回复讨论、按持方筛选和时间排序。
- 社群成员可在「查看成员持方」中查看彼此的当前选择；未加入访客只能看到汇总比例。
- 投票也可独立选择匿名，持方列表显示「匿名成员」，票数仍计入比例。已投票的成员可切换昵称／匿名展示，改变持方不会取消匿名设置。
- 每条观点和回复可选择昵称或匿名发表；匿名记录的对外接口不返回作者昵称和用户 ID，作者仍可移除自己的发言。
- 持方人数、比例、评论和角色通过实时推送同步；隐藏页面暂停同步，返回页面时自动核对，断线后自动退避刷新。
- 每人每题只有一个当前持方；改变持方不改变历史发言的立场。
- 支持用户名＋密码注册、登录和修改密码。跨设备保留原有社区角色、发言和持方；已有昵称成员可为当前身份设置账号。
- 登录使用 30 天 HttpOnly Cookie；密码使用独立随机盐与 scrypt（N=16,384、r=8、p=5）保存，会话和邀请仅存 SHA-256 摘要。修改密码撤销其他设备会话。
- 支持手机布局、邀请链接复制、二维码 SVG 下载、社群切换与新建社群。
- 支持中文／英文界面；右上角「中文 / EN」可切换，登录和管理弹窗内也有入口。记住当前设备的选择，优先使用链接中的 `?lang=en` 或 `?lang=zh`；首次访问依据浏览器语言。邀请链接和二维码保留所选语言。成员发布的辩题、观点、回复和昵称保留原文。

## 本地启动

环境：Node.js 22.13+，pnpm 11.25。应用代码在 `app/`。

```powershell
cd app
pnpm install --frozen-lockfile
pnpm db:local
pnpm dev
```

打开终端打印的地址，默认为 `http://127.0.0.1:5173`。`db:local` 应用尚未执行的迁移；首次运行会在忽略跟踪的 `app/.dev.vars` 中生成随机 `ADMIN_KEY`。

初始宁诺群主可在「登录 / 注册 → 初始群主口令入口」输入 `.dev.vars` 中的口令，随后为原群主身份设置用户名和密码。也可运行 `pnpm owner:setup`，在忽略跟踪的 `app/outputs/owner-account.md` 中取得有效期 24 小时的一次性设置链接。该链接和二维码仅供群主本人使用，设置成功即失效。不要把口令或群主设置链接发给普通成员。

设置账号后，在其他设备使用相同用户名和密码登录即可恢复身份。用户名支持 2–32 个字符，可含中文、英文字母、数字、点、下划线或短横线，以中文、字母或数字开头，不含空格；英文部分大小写不敏感。密码为 10–128 字符，不会去除首尾空格。昵称用于社区展示，用户名仅向本人展示。快速昵称参与仍可使用，但清除 Cookie 或退出后无法恢复；应在「我的社群 → 设置用户名和密码」绑定账号。暂未提供邮件／短信密码找回；请妥善保存密码。

## 每周使用

1. 群主／管理员点击「发布辩题」，填写辩题、背景与双方立场。
2. 点击「邀请伙伴加入」，复制链接或下载二维码，发送给社员。邀请转发给谁，谁就可以使用；过期或撤销后无法加入。
3. 社员扫码，填写 2–20 字昵称并注册账号；已有账号者登录即可加入。也可先用昵称快速参与，再绑定账号。开启入群审核后，等待群主或管理员同意，页面会自动刷新权限。选择持方后发言。
   发言框下可勾选「匿名发表」，其他人会看到「匿名辩友」。选择持方前可勾选「匿名投票」，持方列表会显示「匿名成员」。两项设置相互独立，社群成员仍可查看观点正文、回复和投票所属持方。
4. 页面右上角「成员管理」可以查看成员和待审核申请。群主在某位已加入成员右侧点击「设为管理员」，无须共享口令。
5. 群主在「管理社区与讨论」中开关「入群需审核」。关闭审核后已有待处理申请仍需审核。成员可从自己的昵称进入「我的社群 → 退出当前社群」。
6. 辩题下方可「修改辩题」「撤回辩题」；撤回后只有管理员和群主可见，可从全部辩题选择并恢复。训练结束时使用「结束讨论」，保留历史内容供成员复盘。

## 验证与构建

启动本地服务后运行集成测试。测试创建独立的 `qa-*` 社群，不应指向线上环境。

```powershell
pnpm typecheck
pnpm test:api
pnpm test:accounts
pnpm test:passwords
pnpm test:usernames
pnpm test:management
pnpm test:i18n
pnpm build
pnpm format:check
```

集成测试覆盖成员与管理员权限、跨社群隔离、邀请与撤销、并发持方去重、持方变更、评论与回复、讨论关闭、公开私密切换、会话注销、跨域写入与超长请求拒绝。
另覆盖成员持方明细、匿名作者信息脱敏、匿名回复、匿名发言移除权限、实名与匿名逐条切换，以及公开访客的身份信息隔离。
匿名投票测试覆盖成员及群主的身份脱敏、票数去重、设置恢复、昵称／匿名切换，以及改变持方时的匿名设置保留。
语言测试覆盖中英文文案、占位参数、后端报错、语言优先级和邀请链接。设置 `TEST_ORIGIN=http://127.0.0.1:5173` 后还会检查本地页面的服务端语言渲染。

## 上线

前端为 React + TypeScript，使用 Vinext 的路由和 Cloudflare Workers 运行时，结构化数据存储于 Cloudflare D1（SQLite）。

### Cloudflare 免费方案

当前使用地址：[DebateHub · 宁诺例辩](https://debatehub-unnc.pages.dev)。社区默认私密；账号统一使用用户名和密码登录，成员仍需有效邀请才能加入私密社群。

使用 Cloudflare 账号直接部署，不需要先提交或推送 GitHub，也不需要购买域名。网站使用平台提供的 HTTPS 地址；选择 Workers Free，首版不需要 R2、付费套餐或其他收费服务。

```powershell
cd app
pnpm exec wrangler login
pnpm exec wrangler d1 create debatehub-unnc --location apac
pnpm deploy:cloudflare --database-id <上一步返回的真实数据库UUID>
```

如果登录确认后 `localhost:8976` 显示无法访问，改用官方的设备授权方式，无需本机回调：`pnpm dlx wrangler@4.151.0 login --device`。在 Cloudflare 页面输入终端给出的短验证码并确认，终端显示登录成功后继续部署；不要分享或提交 OAuth 令牌。

部署前请保留 `app/.dev.vars` 中本地生成的随机 `ADMIN_KEY`，该文件只能包含这一项。脚本会重新构建、应用全部线上迁移，并将口令作为秘密环境变量随版本上传。口令和 Cloudflare 授权凭证不会进入源码或 Git。首次使用前应确认账号中没有同名的其他 Worker；需要自定义时传入 `--name`、`--database-name` 和 `--account-id`。

数据库 ID 与部署配置保存在忽略跟踪的 `app/.sites-runtime/cloudflare/` 中，同一台电脑后续更新可直接运行 `pnpm deploy:cloudflare`。换电脑后需要重新提供真实数据库 ID；请复用原数据库，不要重复创建。`pnpm deploy:cloudflare --dry-run` 只构建并检查产物，不修改线上资源。

部署成功后，初始群主通过一次性设置链接或「登录 / 注册 → 初始群主口令入口」设置自己的登录账号。发布本周辩题，再通过「邀请伙伴加入」生成线上邀请链接和二维码。初始社区仍为私密，本地测试社群和讨论不会被上传。

原 `workers.dev` 入口的手机访问失败，已换用上方 Pages 地址。本机不使用代理的首页与接口访问，以及 12 项线上检查均已通过，包括静态资源类型、访客隔离、群主登录、跨域保护、原有数据和邀请生成。仍应使用社员实际的校园网和手机网络验证入口。新二维码为忽略跟踪的 `app/outputs/ningnuo-invite-pages.png`；邀请到期后请在网站内重新生成。

Pages 入口通过 Cloudflare 内部服务绑定访问原 Worker，继续使用原数据库和权限；静态资源由 Pages 提供，不把管理员口令复制到 Pages。项目已创建且发布，日后更新入口运行 `pnpm deploy:pages`。在新的 Cloudflare 账号首次部署时，需要增加 `pages:write` 授权，并创建 Pages 项目：

```powershell
pnpm exec wrangler pages project create debatehub-unnc --production-branch main
pnpm deploy:pages
```

`pnpm deploy:pages --prepare-only` 只准备发布包；`--name` 可指定已有 Pages 项目的名称。未来更新应用时，应先执行 `pnpm deploy:cloudflare` 更新后台，再执行 `pnpm deploy:pages`，使网页资源与后台版本一致。备用入口也需要通过手机实际网络验证，不能仅凭发布成功判断可达。更换入口后应生成使用新域名的邀请二维码；两个域名的浏览器登录状态相互独立。

免费额度并非无限：当前 Workers Free 为每日 100,000 次动态请求；D1 为每日 500 万行读取、10 万行写入和总计 5 GB 存储。实时连接正常且没有新动态时，每约 60 秒做一次状态校验；50 名成员一小时约 3,000 次定时状态请求（此前每 2 秒刷新约 90,000 次），另有首次加载、连接、发言和变化后的更新请求。推送使用支持免费方案的 SQLite Durable Objects 与 WebSocket Hibernation，其独立额度以 [Durable Objects 官方定价](https://developers.cloudflare.com/durable-objects/platform/pricing/) 为准。试用时请关注控制台的实际使用量；免费额度用尽会导致访问或查询受限，不会自动升级套餐。额度以 [Workers 官方定价](https://developers.cloudflare.com/workers/platform/pricing/) 和 [D1 官方定价](https://developers.cloudflare.com/d1/platform/pricing/) 为准。

### Sites 托管配置

- `.openai/hosting.json` 保存已有 Sites 项目 ID 和 `DB` 绑定，不存放口令。
- `db/schema.ts` 是数据结构定义，`drizzle/` 保存增量 SQL 和迁移元数据。
- 上线前在托管平台配置秘密环境变量 `ADMIN_KEY`，并应用全部迁移。
- 网站入口需要允许公网访问，社群是否公开由应用内的群主设置。初始社群仍为私密。
- 使用线上域名生成邀请二维码；`127.0.0.1` 的本地二维码不能供其他手机远程访问。
- 发布流程需同步源码到 Sites 的托管源码仓库；本项目未经明确授权不会自动执行 Git 提交或推送。

当前支持多社群独立权限、实时变化通知、条件读取、按版本复用缓存与事务内统计计数。选中辩题的评论仍全量可读，超长讨论后续应增加分页或增量同步。可运行 pnpm test:capacity 进行仅本机的 100 连接与混合读写测试，以及 50 人集中注册、登录测试；报告位于忽略的 app/test-results/capacity.json。本地结果不是线上容量保证。D1 数据在重新发布后保留，本地和线上数据库相互独立。
