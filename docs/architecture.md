# DebateHub 架构与边界

## 请求与数据

浏览器通过 `/api/state?community=<id>&topic=<id>` 读取当前社群、身份、辩题、统计和讨论。页面通过每个 Community 独立的 Durable Object 接收 WebSocket 变化通知（仅包含 invalidate，不携带评论或成员资料）。服务端合并短时间内的通知，客户端最多每两秒响应一次批量变化；本人写入后立即读取。连接正常时每约 60 秒校验一次，断线时约 10 秒轮询，并在错误时退避到 120 秒。隐藏页面关闭连接并暂停同步，重新显示或联网时重连并核对状态。应用层 ping/pong 通过 Hibernation 自动响应，不保持 Durable Object 常驻。

API 使用参数化 SQL 访问 D1。社区、成员、辩题都在服务端鉴权；客户端隐藏按钮仅用于交互。持方与评论中的 topic ID 必须属于请求指定的 community ID。邀请凭证在 URL fragment 中，不会作为页面请求 URL 发给服务器，也不会出现在请求的 Referer 中；加入时通过 JSON POST 校验。

| 表                   | 用途与约束                                                                                   |
| -------------------- | -------------------------------------------------------------------------------------------- |
| communities          | 社群名称、介绍、公开／私密                                                                   |
| users                | 浏览器身份与昵称，初始群主引导标识                                                           |
| memberships          | 社群与成员的复合主键；owner / admin / member；每社群最多一位群主                             |
| membership_requests  | 社群与用户唯一的最新申请状态 pending / approved / rejected / removed，申请与处理时间、处理者 |
| sessions             | 摘要凭证与过期时间，身份可跨本人加入的社群使用                                               |
| account_credentials  | 唯一规范化用户名与唯一 user ID；密码哈希包含算法、迭代次数与独立随机盐                       |
| account_setup_tokens | 初始群主的短期一次性账号设置凭证，仅保存摘要；不创建或转移角色                               |
| topics               | 所属社群、辩题、背景、双方立场、开放／关闭状态                                               |
| votes                | topic + user 唯一，重试与并发请求不会重复计数                                                |
| comments             | 所属辩题、作者、发表时持方、正文、根评论 ID、移除标志                                        |
| invites              | 邀请摘要、所属社群、有效期与撤销标志                                                         |
| rate_limits          | 按分钟计数的持久化写入限流                                                                   |

## 角色

群主是创建该社群的成员。普通成员也能创建独立社群。管理员由该社群群主从现有成员中任命；管理员不能任命其他管理员、改变群主角色或修改社群可见性。管理员与群主均可发布辩题、管理讨论、邀请成员。其他社群中的角色不产生额外权限。

群主和管理员均能查看完整成员与待审核申请、审核入群及移出普通成员。管理员不能移出群主或其他管理员；群主可移出管理员，但不能移出自己。成员及管理员可自行退群，删除当前成员关系并保留账号、其他社群和历史投票／观点；群主暂不提供退出或转让。

`communities.join_approval` 默认为 0，保留既有邀请直接加入。开关仅由群主控制，开启后将新申请写入 `membership_requests`，审批通过才创建 active membership。注册、登录与昵称参与共用加入计划和 D1 batch；在写入时再次检查有效邀请、审核开关及已有申请状态，避免任一入口绕过审核。待审核成员不读取私密内容，公开社群仅允许按访客权限阅读。被拒绝或移出的用户再次申请始终进入审核，即使开关已关闭；已有 pending 申请也不会随开关关闭而自动获准。审批事务条件更新 pending 状态，重复审批返回冲突。该表保留最新结果，不是完整审计日志。

`topics.withdrawn` 默认为 0；`updated_at` 记录最近修改或撤回／恢复时间。撤回不删除数据，成员和公开访客的列表及指定 ID 查询均不返回题目、观点、票单或统计；当前社群管理者仍可查看和恢复。开放状态与撤回状态独立，恢复不意外重开已结束讨论。投票和评论的写入条件同时要求当前成员关系、开放状态和未撤回，在写入时再次校验。修改已参与辩题可调整标题、背景、分类，双方立场标签则以原子条件锁定。

`ADMIN_KEY` 只引导和恢复默认 `unnc` 社群的初始群主，不能直接取得其他社群的管理权。部署时作为秘密环境变量配置，不进入前端或源码。任命管理员不需要、也不应共享该口令。

## API

所有写请求使用同源 JSON POST，服务端拒绝跨源写入。需要成员身份的接口验证 HttpOnly 会话与成员关系。

| 接口                         | 行为                                                                     |
| ---------------------------- | ------------------------------------------------------------------------ |
| GET /api/state               | 返回当前社群数据，私密社群访客仅收到加入页面所需的简介                   |
| GET /api/communities         | 当前身份已加入的社群及各自角色                                           |
| GET /api/members             | 群主和管理员查看全部成员、角色与待审核申请                               |
| POST /api/admin/login        | 初始宁诺群主口令登录                                                     |
| POST /api/auth/register      | 受邀注册，或为当前昵称身份绑定账号；初始群主可凭一次性设置凭证绑定原身份 |
| POST /api/auth/login         | 用户名密码登录；已有社区角色恢复，有效邀请可加入其他社群                 |
| POST /api/auth/password      | 验证当前密码后更改密码，撤销全部旧会话并签发当前新会话                   |
| POST /api/auth/setup-link    | 尚未设置账号的初始群主生成 24 小时有效的一次性设置链接                   |
| POST /api/join               | 验证邀请并创建身份／成员关系                                             |
| POST /api/logout             | 删除服务器会话并清除 Cookie                                              |
| POST /api/communities/create | 已登录成员创建独立私密社群并成为群主                                     |
| POST /api/members/role       | 群主任命／撤销当前社群的管理员                                           |
| POST /api/members/review     | 群主或管理员同意／拒绝 pending 入群申请                                  |
| POST /api/members/remove     | 群主或管理员移出普通成员；群主还可移出管理员                             |
| POST /api/members/leave      | 非群主自行退出当前社群                                                   |
| POST /api/settings           | 群主更改社群公开／私密                                                   |
| POST /api/invites/create     | 群主／管理员创建 7 天有效邀请                                            |
| POST /api/invites/revoke     | 群主／管理员撤销该社群全部邀请                                           |
| POST /api/topics/create      | 群主／管理员发布辩题                                                     |
| POST /api/topics/update      | 群主／管理员修改辩题；已有参与后保持立场名称                             |
| POST /api/topics/withdraw    | 群主／管理员通过 withdrawn 布尔值撤回或恢复辩题                          |
| POST /api/topics/status      | 群主／管理员关闭或重新开放辩题                                           |
| POST /api/votes              | 成员设置或改变持方                                                       |
| POST /api/comments           | 成员以当前持方发言或回复，回复归入根评论                                 |
| POST /api/comments/delete    | 作者或该社群管理人员移除正文，保留讨论结构                               |

持方比例仅计算有明确持方的人数，未选择者不进入分母。没有人选择时正反方均显示 0%。每条历史评论保留发表时持方，换边不会改写历史。

`/api/state` 的 `voters` 仅返回给当前社群的成员，包含每张票的正反方选择。昵称票显示昵称，匿名票统一显示「匿名成员」且 `userId` 为 `null`，群主及管理员也不会收到匿名票的作者信息。匿名票的排序不使用真实昵称。公开社群的未加入访客仍可看到汇总统计，但不会收到持方成员名单。

评论表的 `anonymous` 标记按每条观点／回复独立保存，默认关闭，因此历史发言仍为昵称发表。匿名记录对所有客户端（含群主／管理员）使用「匿名辩友」且 `userId` 为 `null`；`isMine` 仅向作者本人标记为 `true`，用于展示本人移除按钮。删除操作继续由服务端根据数据库中的作者 ID 鉴权，匿名不会扩大删除权限。

投票表有独立的 `anonymous` 标记，`myVoteAnonymous` 仅返回当前身份自己的选择，刷新后会恢复该设置。投票接口省略匿名选项时保留已有值，显式提供布尔值时才更改；这能避免换边或请求重试意外恢复昵称展示。匿名票仍按 topic + user 去重，并参与全部汇总。投票与每条评论的匿名选择互不影响。数据库保留作者关联以支持鉴权，因此匿名面向社群客户端，不向数据库运营者隐藏身份；此前已公开展示的信息无法从其他成员的记忆或截图中撤回。

## 首版取舍

用户名密码通过 `account_credentials.user_id` 绑定既有用户，不根据昵称匹配或合并账号，也不将首位注册者设为群主。受邀注册与账号创建在 D1 batch 事务中完成，唯一约束拒绝重复用户名及重复绑定；一次性群主凭证的检查、绑定及删除同样原子执行。账号密码使用 Node Crypto 原生 scrypt（N=16,384、r=8、p=5、32 字节随机盐、32 字节输出），校验使用定时安全比较；未知用户名也执行相同哈希工作。认证按来源 IP 和规范化用户名摘要限流。所有写入继承同源 JSON 与请求大小检查。

用户名规则由前后端共享，支持 2–32 个 Unicode 字符，允许汉字、ASCII 英文字母和数字，以及非首位的点、下划线、短横线。服务端统一去除首尾空白、按 NFC 规范化并转为小写；英文用户名的既有键值不变。长度按 Unicode 码点计算，包含扩展汉字。浏览器表单与服务端均拒绝内部空格和其他符号，数据库唯一键继续阻止重名。

设置过账号的成员可以跨浏览器恢复同一用户、社区角色和讨论。快速昵称身份仍只在当前浏览器有效，应在退出前绑定账号。本版未提供邮件／短信密码找回、账号合并、群主转让和完整审计日志。初始群主保留部署端口令恢复入口。

同步容量优化：

- 每次状态读取用一条索引连接查询重新核对会话有效期、当前成员角色和社区版本；失效会话、移出成员和公开转私密不依赖缓存权限。
- ETag 绑定社区版本、辩题和当前身份。无变化返回无正文的 304；所有响应仍为 no-store，客户端显式保存验证标记。不同身份不能复用 304 标签。
- 数据库触发器在同一写事务维护成员数、待审核数、正反票数和有效评论数，以及单调递增的社区 revision。迁移回填既有记录，角色变化、匿名切换、软删除、题目撤回与昵称变化都会使缓存失效。
- Worker 内共用按版本隔离的原始讨论快照，仅缓存已完成的普通数据，不跨请求共享待完成 I/O；60 秒过期、24 项与约 8 MiB 大小上限，避免无限缓存。发送前逐个身份重新脱敏与计算 isMine，禁止缓存用户专属响应。每条评论仍全部可读；目前没有服务端评论分页，超长讨论仍会增加首次加载及变化后的流量。
- 学校共享出口下，未登录写入每 IP 600 次/分钟，账号入口每 IP 300 次/分钟，昵称加入每 IP 300 次/分钟；已登录普通操作按用户限流。规范化用户名的 15 次/分钟、评论的 15 次/分钟及管理操作的限制继续保留。
- 密码哈希保留 scrypt N=16,384、r=8、p=5；每个 Worker isolate 同时至多执行两个密码计算，排队至多 128 个、最长 30 秒，超出返回 503 与 Retry-After，不降低密码强度换取容量。
- 每个 Community 的实时通知完全隔离；私密社区握手验证成员与同源 Origin。通知不包含任何讨论正文或身份，后续 HTTP 读取独立鉴权。通知暂时失败不把已提交写入误报成失败，重连与定时校验负责收敛。通道可用时新变化通常在数秒内出现，不提供消息送达保证。

当前邀请是可转发的承载凭证，不绑定指定收件人。D1 与 Worker、Durable Objects 免费每日限额仍然存在；本地压测不能视为线上容量承诺。可用 pnpm test:capacity 在本机隔离社区复测，脚本拒绝公网目标。
